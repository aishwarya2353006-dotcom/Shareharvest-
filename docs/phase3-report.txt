Phase 3: Organizations and Memberships - Implementation Report
=======================================================

FILES CHANGED:
1. backend/organizations/serializers.py:
   - Replaced the incomplete OrganizationSerializer with a complete one (model = Organization, fields = '__all__', read_only_fields for verified_at, verified_by, status, created_at, updated_at).
   - Added MembershipSerializer with user and organization as PrimaryKeyRelatedField, role, joined_at (read-only), is_active.
   - Added validation to prevent duplicate active memberships.

2. backend/organizations/views.py:
   - Implemented OrganizationViewSet with:
     * Queryset filtering for organization-level data isolation (users only see organizations they are active members of; platform administrators see all).
     * PerformCreate method that atomically creates the organization and an owner membership for the requesting user.
     * Custom actions for verification, rejection, and resetting to pending (only accessible by platform administrators).
   - Implemented MembershipViewSet with:
     * Queryset filtering that returns memberships for a specified organization only if the requesting user is an owner or admin of that organization; otherwise returns the user's own memberships.
     * PerformCreate that prevents role escalation (users cannot assign a role higher than their own) and prevents duplicate memberships.
     * Update and destroy methods that prevent changing user/organization fields, prevent role escalation, and prevent removal/deactivation of the last active owner.
   - Added custom permission classes:
     * IsOrganizationMemberOrPlatformAdmin: allows access if user is platform admin or active member of the organization.
     * IsMembershipManagerOrSelfOrPlatformAdmin: allows access if user is platform admin, the membership owner, or an owner/admin of the organization.
   - Added helper function get_user_role_level to compare role hierarchies.

3. backend/organizations/urls.py:
   - Configured a DefaultRouter to register OrganizationViewSet and MembershipViewSet.
   - Generated URL patterns:
     * GET/POST /api/organizations/organizations/
     * GET/PUT/PATCH/DELETE /api/organizations/organizations/{id}/
     * POST /api/organizations/organizations/{id}/verify/
     * POST /api/organizations/organizations/{id}/reject/
     * POST /api/organizations/organizations/{id}/pending/
     * GET/POST /api/organizations/memberships/
     * GET/PUT/PATCH/DELETE /api/organizations/memberships/{id}/

4. backend/organizations/tests.py:
   - Added test cases for:
     * Organization creation and automatic owner membership.
     * Organization listing and retrieval isolation (with pagination-aware assertions).
     * Verification actions (only platform administrators can verify/reject/reset).
     * Membership creation and duplicate prevention.
   - Tests pass.
